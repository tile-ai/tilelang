# TileLang Tuning Agent Installation Guide

This directory is the platform-independent source of truth for the TileLang performance-tuning workflow. The runtime configurations under `.codex/`, `.opencode/`, and `.claude/` are all generated by the installer; do not maintain three separate copies of the workflow content.

## Installation

The target tool must be selected explicitly. Pass `--tool` repeatedly to install for multiple tools at once.
By default, a project-scope installation targets the `agent/` directory containing `init.sh`, regardless of the current directory from which the command is run. This directory is the isolated entry point for TileLang tuning.

```bash
bash agent/init.sh --tool codex --scope project
bash agent/init.sh --tool opencode --scope project
bash agent/init.sh --tool claude --scope project
bash agent/init.sh --tool codex --tool opencode --tool claude --scope project
```

By default, OpenCode selects the permission schema based on the locally installed CLI major version: 1.x uses `classic`, while 2.x uses `v2`. If the CLI is not installed, the installer generates the current stable `classic` schema by default. To pregenerate configuration for another environment, specify the schema explicitly:

```bash
bash agent/init.sh --tool opencode --scope project --opencode-schema classic
bash agent/init.sh --tool opencode --scope project --opencode-schema v2
```

Install into another project's dedicated `agent/` directory:

```bash
bash agent/init.sh --tool opencode --scope project --path /path/to/project/agent
```

Install globally:

```bash
bash agent/init.sh --tool claude --scope global
```

## Safety and Validation

```bash
bash agent/init.sh --all-tools --scope project --dry-run
bash agent/init.sh --check
bash agent/init.sh --tool codex --scope project --check
bash agent/init.sh --tool opencode --scope project --uninstall
```

The installer manages only files registered in `tilelang-tuning-manifest.json`. It stops when it first encounters an unmanaged file with the same name. Use `--backup-existing` to back it up before installation, or explicitly use `--force` to overwrite regular files and symbolic links. `--force` never deletes real directories.

## Launch

- First enter the dedicated directory: `cd agent`
- Codex: `codex`
- OpenCode: `opencode .`
- Claude Code: `claude`

A project installation generates a short `AGENTS.md` under `agent/`, allowing Codex and OpenCode to load their respective installed complete `tilelang-tuning` workflows automatically. Claude Code imports that entry through `CLAUDE.md` in the same directory. `core/` remains the sole source of truth for the complete workflow; the installer does not copy the full text into entry-point files.

When Codex, OpenCode, or Claude Code is launched from the repository root, it does not load the entry instructions under `agent/`, so ordinary development sessions remain unaffected. When launched from `agent/`, tuning artifacts are written to `agent/operators/` as specified by the workflow.

A global installation has no fixed project entry point, so the `tilelang-tuning` agent must still be selected explicitly. A global installation does not create `AGENTS.md` or `CLAUDE.md` in the user's home directory.

## Directory Responsibilities

- `core/agents/`: platform-independent agent definitions.
- `core/workflows/`: platform-independent workflows and fixed task templates.
- `adapters/`: runtime-format templates for Codex, OpenCode, and Claude Code.
- `manifest.json`: agent names, roles, subagent relationships, and the skill inventory.
- `scripts/install.py`: rendering, installation, validation, and uninstallation logic.

The repository's existing `tests/` directory remains unchanged. This installer does not add a separate Python test directory; `--check` performs static validation.
